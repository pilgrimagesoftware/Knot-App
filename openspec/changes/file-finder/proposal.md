# Proposal

## Why

The Swift app had a fuzzy file finder (#5): an overlay opened with ⌘⇧F
(Edit > Find File…) over the active agent's folder, a debounced query, a
ranked list with the matched characters marked, keyboard selection, and a
callback that hands the chosen path back. The port has no finder.

It does have half of one. The panel composer's `@` lookup
(`panel-file-mentions`) already ports `FileSearchService`'s listing - git
`ls-files`, the same exclusion set, the 50,000 cap, gathered off the render
path and cached per agent. But it ranks with its own greedy scorer
(`panel_commands/fuzzy.rs`), not `FuzzyScorer`, though its spec says the
reference's matching moved over "unchanged in substance". It did not:
`FuzzyScorer` is VS Code's dynamic-programming matcher, and a greedy walk
picks the first occurrence of each character. That is the approximation the
issue warns makes a finder feel broken without failing a test.

## What the finder is for

In the reference, a selected path is copied to the clipboard and typed into
the active agent's terminal (`ContentView.swift:86`): a way to name a file to
the agent without typing its path. The port keeps that purpose:

- **Terminal-mode agent**: the path is typed into the agent's terminal at
  the prompt, without Enter - the reference's `sendText`.
- **Panel-mode agent**: the path is inserted into the composer at the caret,
  as an `@` mention completes one.

Callers: the workspace window, opened from Edit > Find File… (⌘⇧F) for the
selected agent. A detached workspace is the same window type in the port, so
it gets the finder too.

## What Changes

- **One scorer, ported exactly.** `FuzzyScorer` becomes a Rust module,
  checked against a snapshot generated by the Swift scorer itself
  (`reference/`), and the `@` lookup switches to it from the greedy scorer.
- **The finder overlay.** Opened from Edit > Find File… (⌘⇧F) for the
  selected agent: a query field that holds focus, results updated 150 ms
  after typing stops, the reference's top 50, matched characters marked, ↑/↓
  to move, Return or a click to choose, Esc or a click outside to dismiss.
  "Too many files" and "No matching files" states as in the reference, plus
  a gathering state while the listing is built.
- **Off the render path and cancellable.** The finder reuses the agent's
  cached listing (`panel_commands::files`), so opening it does not walk the
  folder again. Scoring runs on a background task; each query supersedes the
  last, and a result for a query that is no longer current is discarded.

## Carried over, changed, dropped

| Reference behaviour | In the port |
| --- | --- |
| `FuzzyScorer` ranking and matched indices | Carried over exactly, snapshot-tested |
| Sort by score (unstable) | Changed: ties broken by path, so the order is deterministic |
| Indices are Swift `Character` (grapheme) offsets | Changed: `char` offsets; differs only inside combining sequences |
| 150 ms debounce, top 50, 50,000-file cap, exclusion set | Carried over (cap and set already ported) |
| Empty query lists nothing | Carried over |
| Keyboard: ↑/↓ clamp, Return chooses, Esc dismisses | Carried over |
| Click outside dismisses; switching agent closes it | Carried over |
| Selection types the path into the terminal | Carried over; in Panel mode inserted into the composer instead |
| Selection also copies the path to the clipboard | **Dropped**: it overwrites the clipboard as a side effect the user didn't ask for, and the path is already where it is needed |
| Per-extension file icons | **Dropped**: one file icon; a table of SF Symbol names has no equivalent in the port's icon set |
| Finder in the detached window | Changed: reachable. The reference declared it but nothing ever opened it there |
| Walk restarted every time the finder opens | Changed: the agent's cached listing is reused, refreshed on folder change as `panel-file-mentions` already requires |

## Impact

- `knot`: a `fuzzy_score` module (the port) replacing
  `panel_commands/fuzzy.rs`'s scorer; a `file_finder` overlay in the
  workspace window; an Edit menu item and ⌘⇧F binding; l10n keys.
- Specs: new capability `file-finder`; MODIFIED `panel-file-mentions`
  "Matching is fuzzy and ranked"; ADDED `app-menu` "Edit > Find File…".
- Not in this change: anything the reference did not do (frecency, typo
  tolerance, searching file contents).
